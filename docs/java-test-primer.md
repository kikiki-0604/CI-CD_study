# テストコードの読み方・書き方(Java 入門メモ)

`SuggestionServiceTest.java` を読み書きするために**必要なことだけ**をまとめました。
Java を書いたことがなくても、**ヒントのコードを写して、少し変える**ことができれば大丈夫です。
他の言語(JavaScript、Python など)の経験があれば、「あれのことか」と対応づけながら読んでください。

## 1. テストとは何か

**「こう動くはず」を、コードで書いて、自動で確かめる仕組み**です。

```java
@Test
void 足し算ができる() {
    int result = 1 + 2;                      // 実行: 試したいことをやる
    assertThat(result).isEqualTo(3);         // 検証: 結果が、期待どおりか確かめる
}
```

- `@Test` が付いたメソッドが、**1つのテスト**です。
- 検証が**1つでも外れる**と、そのテストは**失敗**します。外れなければ**成功**です。

このファイルのテストは、すべて次の**3段構成**で書かれています。

| 段階 | 何をする | 例 |
| --- | --- | --- |
| **準備** | 「AI がこう返してきた」という状況を作る | `stubBedrock(bedrockResponse(...));` |
| **実行** | 試したいメソッドを呼ぶ | `var result = service.suggest(List.of("卵"));` |
| **検証** | 結果が期待どおりか確かめる | `assertThat(...).hasSize(5);` |

## 2. このテストが、何をしているか

アプリは、食材を渡すと **AI(Bedrock)に問い合わせて、料理の候補を返す**(`SuggestionService`)機能を持っています。
ただし、テストでは**本物の AI を呼びません**(遅い、お金がかかる、毎回答えが違うため)。

代わりに、**偽物(モック)**の AI を用意します。

```
本番:  SuggestionService  →  本物の BedrockClient  →  AI
テスト: SuggestionService  →  偽物の BedrockClient  →  こちらが決めた応答を返すだけ
```

こうすることで、**「AI が壊れた応答を返したら?」「5件未満しか返さなかったら?」**といった、本物ではなかなか起こせない状況を、いつでも再現できます。

## 3. 出てくる書き方の早見表

### 変数と型

| 書き方 | 意味 |
| --- | --- |
| `String text = "こんにちは";` | 文字列の変数 |
| `var result = ...;` | 型を、右側から自動で決める(JavaScript の `const` に近い) |
| `List.of("卵", "玉ねぎ")` | 文字列のリスト(配列のようなもの)を作る |
| `;` | 文の終わり。**Java では、ほとんどの行の最後に必要**です(忘れるとエラー) |
| `{ ... }` | まとまり(メソッドやクラスの中身)を囲む |
| `// ここは説明` | コメント(実行されない)。`/* ... */` や `/** ... */` も、コメント |

### 文字列

| 書き方 | 意味 |
| --- | --- |
| `"abc" + "def"` | 文字列をつなげる |
| `"""` ... `"""` | **複数行の文字列**(テキストブロック)。JSON を書くときに使う |
| `\"` | 文字列の中で、`"` を表す(例: `"{\"name\":\"A\"}"`) |
| `\n` | 改行 |

### ラムダ式(矢印の書き方)

`link -> link.site()` は、**「`link` を受け取ったら、`link.site()` を返す」という、小さな関数**です(JavaScript の `link => link.site()` と同じ)。

```java
links.stream().map(link -> link.site())     // リストの各要素から、site だけを取り出す
```

`stream().map(...)` は、「リストの各要素を変換する」(JavaScript の `.map()` と同じ)です。

### assertThat(検証)

`assertThat(実際の値)` の後ろに、**期待する条件**をつなげます。

| 書き方 | 意味 |
| --- | --- |
| `.isEqualTo(450)` | 値が、450 と等しい |
| `.hasSize(5)` | リストの要素数が、5 |
| `.contains("卵")` | 文字列に「卵」が含まれる |
| `.containsExactly("A", "B")` | リストの中身が、**この順番で、これだけ** |
| `.isNotNull()` | null ではない |

```java
assertThat(result.candidates()).hasSize(5);                       // 候補が5件
assertThat(result.candidates().get(0).name()).isEqualTo("オムライス");  // 1件目の名前
```

> 💡 `.get(0)` は「0番目(= 最初)の要素」です。Java では、**数え始めが0**です。
> 💡 `candidate.name()` のように、**`()` を付けて**値を取り出します(`name` ではなく `name()`)。

### 例外のテスト(`assertThrows`)

「**例外が出ること**」を確かめます。

```java
assertThrows(AiResponseException.class, () -> service.suggest(List.of("卵")));
```
- 意味: 「`() -> ...` の中を実行すると、`AiResponseException` が投げられるはず」
- **例外が出なければ、このテストは失敗**します。

### Mockito(偽物の BedrockClient を操作する道具)

| 書き方 | 意味 |
| --- | --- |
| `Mockito.when(A).thenReturn(B)` | 「A が呼ばれたら、B を返せ」と指示する |
| `Mockito.anyString()` | 「どんな文字列でも」を表す |
| `Mockito.verify(偽物, Mockito.times(2)).invoke(...)` | 「`invoke` が、**ちょうど2回**呼ばれたか」を確かめる |

このファイルでは、`stubBedrock(...)` という**道具**に、まとめてあります。**ほとんどの場合は、これを呼ぶだけ**です。

```java
stubBedrock(bedrockResponse(FIVE_DISHES_JSON));      // 「AIが、5件の料理を返した」状況を作る
```

## 4. 問題を解くときのコツ

1. **まず、問1・問2を、よく読む**。ほとんどの問題は、これの**変形**です。
2. 問題のコメントの **「ヒント1、2、3…」を、順番に**やる。**コメントのコードは、そのまま写して構いません**(ただし、意味を考えながら)。
3. **1問書いたら、すぐ実行**して確かめる。まとめて書くと、どこが間違っているか分からなくなります。
4. 迷ったら、**他の問題の書き方**を、見に行く(同じ道具を、別の問題でも使っています)。

## 5. エラーの読み方

### コンパイルエラー(書き方が間違っている)

実行の前に、**Java の文法チェック**で止まります。

```
SuggestionServiceTest.java:95: error: ';' expected
```
- **ファイル名**、**行番号**(この例では95行目)、**何が悪いか**が出ます。
- **よくある原因**:

| メッセージ | 原因 |
| --- | --- |
| `';' expected` | 行の最後の `;` を忘れている |
| `cannot find symbol` | **名前の打ち間違い**、または、道具が使えない場所にある |
| `incompatible types` | 値の型が合っていない(例: 数字が入る場所に、文字列を入れた) |
| `unclosed string literal` | `"` の閉じ忘れ |
| `class, interface, enum, or record expected` | `}` の数が合っていない |

### テストの失敗(期待と、実際が違う)

```
Expecting actual:  3
to be equal to:    5
```
- **「実際の値は 3 だったが、期待は 5 だった」**という意味です。
- 書いた**期待値が間違っている**のか、**準備(モックの設定)が足りない**のかを、考えます。

## 6. よくある質問

| 質問 | 答え |
| --- | --- |
| `@Disabled` と `fail(...)` は、消してよいの? | **はい。問題を解くときは、この2行を消します**(消さないと、テストが動きません) |
| `import` は、足す必要がある? | **ありません**。必要なものは、すべてファイルの最初に書いてあります(使っていない `import` の警告は、出ても問題ありません) |
| メソッド名が日本語でいいの? | はい。テストでは、**何を確かめるか**を日本語で書くと、分かりやすいです |
| `var` と書く場所と、書かない場所があるのは? | `var` は、**型を自動で決める書き方**で、どちらでも動きます。ヒントのとおりに書けば大丈夫です |
| テストが成功したのに、本当に正しいか不安 | **わざと期待値を間違えて**、テストが失敗するか試してみてください(失敗すれば、ちゃんと確かめられている証拠です) |
